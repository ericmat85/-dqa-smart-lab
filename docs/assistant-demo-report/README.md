# AI 助理 Demo 報告指令

在實驗室「試驗委託」頁的 AI 智慧助理輸入 `/create a demo report`，選擇由目前帳號執行、已完成全部試驗流程的虛擬委託，再按「產生並檢查報告」。可下載 Excel，或下載並帶入既有提交視窗；本人仍須確認簽名後才能提交。

圖示案件的填入名稱為「高溫高濕」，後端上傳綁定卻要求試驗目錄的完整名稱「高溫高濕放置試驗」。新生成器以伺服器讀取的本案試驗 ID 解析完整名稱，保留原本上傳驗證規則，產生後實際呼叫與提交相同的 `validateHumanFile` 驗證。不能以模型輸出、檔名或預設成功標記跳過審查。

如案件送簽時綁定自訂試驗報告範本，使用當時的固定版本及儲存格對應，保留原代入欄位與範本雜湊，在系統簽核頁填入合成摘要並新增清楚標示的 Demo 試驗紀錄。未綁定時使用本案內建試驗版型。委託單與報告原稿皆不被改寫。生成的檔案保留虛擬用途工作表及列印頁首，不加入主管／執行人簽名。

生成器以目前會話及固定租戶讀取資料；伺服器檢查虛擬種類、完成狀態、指派執行人、報告權限與委託／排程版本，產生後重新讀取資料與權限。真實、未完成、未指派或已變更的案件不能取得文件。操作不建立上傳意圖、不更新案件狀態、不執行簽核或呼叫付費模型。

提交視窗移除「DEMO 填入」、「下載本案 Excel 範本」、「下載目前 Excel 報告」及相關 Demo 限制／說明。AI 審查狀態放在視窗上方，仍標明 Demo 規則驗證；保留手動上傳、重新檢查與本人簽名流程。

原有報告上傳上限維持 20 MB。助理產生的下載回應限 3 MB，避免超過 API JSON 回應大小；一般性能版型隨函式包附帶，內建生成不塞入大型合成照片。自訂範本過大時會停止生成並提示縮減圖片。

本次不需資料庫 migration，也不更動已儲存的成員預設簽名。維持 PR49 與受保護 Preview，不合併主線或部署 Production 前端。

## 上傳憑證驗證修正

報告內容檢查通過後，上傳意圖仍須由 API 以固定報告金鑰產生 HMAC 憑證，交由資料庫核對上傳 UUID、檔案 SHA256、位元組長度與 MIME。`BUSINESS_REPORT_ATTESTATION_KEY` 與資料庫既有 `report_key` 對齊；`BUSINESS_COOKIE_KEY` 只負責會話，不再用於產生報告憑證。建立新預覽時只輪替 Cookie 金鑰，並以唯讀雜湊核對固定報告金鑰一致性。

此修正不輪替資料庫金鑰、不改動簽核規則或業務資料；已下載且內容正確的 Demo 報告可在新預覽重新上傳提交。回歸測試以實際 Node 憑證提交到隔離 PostgreSQL，涵蓋更換 Cookie、舊錯誤重現、竄改檔案參數拒絕及簽核後 PDF 封存，所有合成資料回滾。
