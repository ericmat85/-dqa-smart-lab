# 環境複合連續試驗與 UI 巡檢

在電子委託系統新增「專案」時，選擇「環境複合連續試驗」，依序加入 2–20 個階段，設定同一批樣品數量、階段名稱、總工時、試驗條件與判定基準。系統建立一張專案子委託；原有獨立分項模式仍逐項建立委託。各階段工時代表整批樣品的暴露／操作時間，不會乘上樣品數。固定工時試驗維持既有條件。

一階審查與排程管理使用相同的接近全螢幕視窗。逐階指定設備，可跨階重用同一台設備，最多使用既有預約機制支援的四台設備。每台都須容納完整樣品批次。選用的所有設備與執行人，會保留整串起訖期間，以保證切換時可用；此版不會在中間階段釋出設備。

各階段以分鐘精度直接相接，不會補等待時間或延長試驗。切換與最後收尾限定週一至週五作業時段，預設 09:00–18:00，可在排程中核對調整。需人員操作的階段須完整位於同一工作時段；標示為連續運轉的設備須在台帳設定全天運轉。設備是否實際支援各階段條件仍須由一階主管核對台帳規格與試驗規範。此版本採週一至週五工作日，尚未匯入國定假日行事曆。

排程頂部的「整串完成時間」會列出最後階段的運轉方式、起訖時間（含星期）與完成點檢查結果。最後階段若需人員操作，整段須在同一工作日的上班時段內完成；即使結束點是星期一，也不能把人員操作跨過週末。完成點落在休息時間或週末會阻擋確認，不會延長前一階段、插入等待或順延至下個工作日。

若首段為高溫乾燥且已預置樣品、設定定時啟動，可勾選週末開始；執行前準備與簽名仍須在開始前完成。其餘階段不允許假日切換。起點不合時，可尋找未來 21 天符合銜接時段的候選起點；候選只核對時間，仍須通過後端全設備與人員衝突檢查。若沒有可行起點，應重新核對協議，系統不會修改已簽核的工時。

簽核階段會驗證目錄修訂版、設備容量／狀態／修訂版、執行人資格、資料權限與整串占用；任一衝突會整筆回滾。樣品編號仍在確認排程後產生，一階簽名後二階簽核，再由執行人完成準備與確認。委託資訊會顯示已簽核階段，既有文件、報告綁定與送簽版本保持獨立；複合報告需另在文件設定綁定適用範本，不會冒用單項試驗範本。

Migration 049 增加複合試驗目錄項目及檢查函式。普通單項排程委派至原 048 計算函式。新目錄透過工作區範圍的 metadata 提供給新版後端，舊版目錄快照不會收到無單一固定工時的複合項目，避免影響舊部署。此遷移不會回填既有委託、改寫簽名、範本、綁定或設備預約。

共用 UI 修正包含真正等寬高的圓圈與頭像、數字／圖示垂直置中、簽名與表單間距、刪減巢狀框線、管理卡片間距，以及手機填單導覽與 AI 浮動按鈕的避讓。檢查涵蓋三個系統的桌面與手機頁面；合成案例與所有實際 SQL 回歸驗證在隔離、無網路的本機資料庫執行並回滾。

驗證採用目前的 `verify_preflight_sequence.py`、專案、共享排程、預覽、範本階段、虛擬執行與整日排程套件，加上新的複合排程 SQL 測試。舊 `verify_preapproval_scheduling.py` 仍在排程前儲存樣品編號，與 migration 048 的現行順序不符；在套用 049 前的隔離 048 基準亦有相同 40 項失敗，因此不列為通過測試。新舊版目錄相容性另以實際已登入工作區的唯讀快照驗證：原目錄 20 項、新版 metadata 1 項，沒有寫入案件。
