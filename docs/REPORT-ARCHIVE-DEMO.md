# Demo 報告產生與封存資料庫

本次接續 `codex/demo-report-quickfill`，全部使用假資料；不接公司資料庫、不變更部署保護、不自動合併。

## 展示流程

1. 實驗室已完成案件按「提交報告」→「DEMO 填入」，只產生 Excel 與展示簽名，並執行現有規則；不產生 PDF、不直接送審。
2. 使用者按「提交」，進入二階主管審核。退回後仍須補件重送。
3. 二階、三階主管依序簽核，禁止自審及跨階簽核同一案件；完成後仍為「待查閱」。
4. 指定的**委託者主管**按「確認查閱並封存」，才開始產生完整 PDF，保存於本機 IndexedDB，案件成為「已結案」。同 ID 若已改為其他角色，不能執行此確認。
5. 只有封存完成的報告才列在「報告資料庫」，可搜尋、預覽、下載。三系統讀取同一個封存紀錄，不各自產生另一份 PDF。

工作中的 Excel 會先存在本機，供簽核及重新整理後繼續操作；這不代表已產生或封存 PDF。PDF 與確認查閱的帳號 ID、時間一同保存。轉換或儲存失敗仍維持待查閱，不顯示成功封存。

## 入口與範圍

| 系統／角色 | 入口與可查閱資料 |
| --- | --- |
| LMS 系統管理員 | 可查閱全部已封存案件 |
| LMS 一／二／三階主管 | 可查閱自己提交或參與簽核的已封存案件 |
| 實驗室工程師／副工程師 | 可查閱自己提交或參與簽核的已封存案件 |
| 電子委託：委託者 | 可查閱自己的已封存委託 |
| 電子委託：指定主管 | 可查閱自己負責或曾參與簽核的已封存委託 |
| 自訂 LMS 角色 | 須先在角色頁面勾選「報告資料庫」；案件仍須屬於自己的提交／簽核範圍 |
| 停用、無系統權限或未授權角色 | 隱藏入口，檔案讀取函式也拒絕存取 |

案件來源不存在、未結案、未確認查閱或 PDF 缺失時，不提供下載。下載時重新讀取當下帳號與案件權限，不能只憑舊畫面狀態下載。前端檢查適用於 Demo；正式資料庫需將認證、查詢範圍、稽核及檔案授權搬到伺服器端。

## 已確認的 Excel／PDF 原則

- 一般性能 Demo 以使用者確認的 V4 填滿範例為資料基準，動態帶入本案編號、產品、版次、樣品數量及實際試驗日期。
- 本版型有五個樣品位置，Demo 支援 1～5 支；未使用位置標示 N/A。超過五支會停止，避免漏掉樣品。舊案件無數量時暫以一支展示；正式使用前需補齊原委託資料。
- 日期及環境紀錄依試驗起訖日期填寫，本 Demo 在起、迄日期各設一筆虛擬環境觀測；不把樣品數當成日期筆數。同一天只設一筆，未使用位置斜線註銷。
- ms 以整數；s、min、h 等時間數值保留兩位小數；V 保留一位。套用到條件、判定基準、結果及 PDF，保留尾零。日期與 HH:mm 時刻不改成小數。
- Fuel 顯示各樣品的阻值區間，不以 OK 取代數值。該區間僅供虛擬例子，並非套用所有產品的固定判定標準。
- 已選項目為黑色 ■、未選為 □；簽名／黃色輸入提示於輸出時白底。保留原有表格結構與三方簽名位置。
- 依委託數量放入相應的前／後示意圖，明確標示非實拍。簽名仍由流程中的實際 Demo 操作帳號逐階轉印，範例不預填主管核准紀錄。
- 產出順序仍為委託單 → 選用附件 → 報告；本次未新增附件轉檔，有附件且尚未支援時會阻擋結案，不會略過附件。

## 展示限制

資料庫仍是同網站來源、同瀏覽器的 IndexedDB，不是 Supabase 或公司正式資料庫；清除資料會移除檔案。權限也不跨瀏覽器同步。

PDF 使用瀏覽器端表格重繪；保留七頁一般性能報告、主要表格、數值、示意圖、三方圖片簽名及已知頁尾 Logo。不能宣稱與 Excel 原生列印逐像素相同；複雜圖表、頁首浮動物件及不同版型仍需人工驗收。通常試驗的正式範本未提供，仍使用簡化 Demo 版。

「通過 AI 全檢（Demo 規則模擬）」只代表目前規則全通過，沒有連接真正 AI，不能代表全部測項公差驗證或正式試驗合格。圖片簽名不具正式電子簽章效力。
