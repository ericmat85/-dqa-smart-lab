# 專案委託

委託類型為一般、急件、專案；保留既有 priority 儲存欄位，舊「專案關鍵」顯示為「專案」，其既有單項委託仍可編輯。

新增專案一次填寫共用資料與簽名，可加入 1–100 個獨立分項（支援至少 70 項），每項分別設定數量、試驗手法、判定方式及判定基準。同一目錄試驗可重複加入或複製，以使用不同條件；不虛構新的試驗規範。畫面每頁編輯 10 項。手法與判定文字各限 3000 字；不作判定而未填基準時，寫入「不作判定；僅記錄試驗結果。」。

儲存專案草稿後會產生各自可編輯的關聯草稿；整批送出會產生各自送簽的委託。沒有額外的專案編輯流程；各子委託沿用原有主管簽核、LMS 審查、排程、報告與結案流程。樣品空間 U 仍由原本排程流程填入。專案編號、分項序號與名稱可在委託資訊辨識，並透過原清單搜尋專案編號；既有虛擬委託資訊顯示規則不變。

## 寫入與恢復

- BFF `/projects/prepare`、`/projects/execute`、`/projects/result/:id` 使用正式登入者 Token，工作區取自加密 Session，拒絕由瀏覽器指定 tenant／actor。
- migration 032 使用準備意圖、內容指紋、行鎖與單次 PostgreSQL 交易。100 個子委託全部成功才提交；任一項失敗全部回復。
- 子委託 UUID 與送簽 operation UUID 均從專案 operation＋序號決定，重播同一已成功操作回傳原結果。
- 原本單項每 10 分鐘 100 次的限流保留；專案每位使用者每 10 分鐘最多兩批，每批最多 100 項。限流例外僅允許當前內部交易與確切派生的子委託／操作 ID，不能由公開 RPC 呼叫。
- 瀏覽器只保留 operation ID 與內容指紋，不保存共用表單或簽名。遺失回應時先查鎖定結果，結果未確認前保留原 operation，禁止用修改內容取代未確認的批次。
- 已確認成功後即使清單讀取失敗，仍回報已儲存，不能把讀取失敗當成可再次新增的訊號。
- 專案指令上限 4 MiB；僅完整 UI snapshot 回應上限提高為 8 MiB，以容納 100 項分項說明；其他上游回應上限仍為 2 MiB。
- 主管資料只回傳本人指定、啟用且完成驗證的主管姓名與登入電子郵件，沒有擴大為工作區帳號目錄。

本功能尚待發布及套用 migration 032。開發驗證只使用隔離的合成資料庫，未建立正式專案或寄送通知信。
