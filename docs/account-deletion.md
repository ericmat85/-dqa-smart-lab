# 帳號刪除與管理者密碼確認

已存在的帳號在編輯視窗底部顯示「刪除」，與取消／儲存同列。按下後顯示待刪帳號及目前登入的管理者電子郵件，要求輸入該管理者的系統登入密碼。新增帳號不顯示刪除，且不能刪除目前登入的帳號。

後端先以現有登入身分建立一次性的刪除意圖，再向 Supabase Auth 驗證目前管理者密碼。確認回傳身分相同後，撤銷新建的臨時驗證登入，最後才由伺服器專用 RPC 完成刪除；原管理者登入 Cookie 不變。瀏覽器無法傳送「已驗證」旗標完成刪除，也沒有服務金鑰。

密碼不進入資料庫、操作日誌、網址或瀏覽器儲存。密碼欄位在送出、取消和關閉時清空。每位管理者每 15 分鐘最多建立 5 次密碼確認意圖；意圖 5 分鐘到期。錯誤密碼不變更帳號。結果不明時不自動重送，可查詢原操作或取消尚未完成的操作；取消會阻擋延遲抵達的完成請求。

刪除是工作區帳號的軟刪除：從帳號清單移除、停用並撤銷此工作區登入，保留歷史會員 ID、案件、簽名及稽核紀錄；不刪除跨工作區共用的 Supabase Auth 身分。後續可用同一電子郵件建立新的工作區會員，新會員不會繼承舊會員專屬的歷史案件存取權。歷史資料仍可由原有授權角色查閱。

刪除前及完成時都檢查工作區管理權、帳號版本、最後管理者及待交接事項。仍是其他啟用人員的主管，或仍有未結案委託、未完成排程、借用、設備／物料／品質工作負責項目時，須先交接。新指派會鎖定會員並拒絕已刪除會員，避免與刪除同時操作產生失效指派。
