# 排程先於一階簽名，執行前準備先於啟動

本次調整適用於共用資料庫流程，延續 PR49 的範本、儲存格對應、預覽及系統介面功能。

## 操作順序

1. 委託者送出，直屬主管簽核。
2. LMS 一階主管核對需求，在簽核視窗先確認設備、執行人與排程，再編定並儲存樣品編號，最後簽署委託單。排程編輯器沒有樣品編號輸入欄位。
3. 一階簽名同時保留資源，排程顯示「待二階簽核」。二階主管核准同一份排程後交給執行者；退回則取消保留並釋放設備。
4. 執行者在「填寫試驗前準備」記錄樣品、收樣日、治工夾具、操作熟悉度及委外預約。此步驟保存檢核表，不簽名也不啟動試驗。有異常可以先保存並再開啟修正。
5. 檢核都完成且異常解除後，執行者明確勾選「確認試驗前準備已完成且無異常」並簽名。完成這一步後，試驗才會依排程自動啟動；試驗完成及報告簽核仍走既有程序。

第 4 區的「執行無異常」指的是 **試驗開始前的準備無異常**。它不會在試驗結束時被量測結果覆寫。

## 委外

新增委託的「委託類型」可選「委外」。後端從已送簽的委託類型判斷，排程強制顯示「委外設備」，不接收任何內部設備 ID，不占用設備容量，也不檢查內部設備時段。仍須指定具執行權限的人員，並遵守人員時段限制；不同人員可同時安排委外。準備確認時，委外預約必須選「是」。

## 範本儲存格

- 一階樣品編號、是否委外、委外預計完成日、最多四台設備及其日期、執行人與計畫開始日，全部由本次已確認排程代入，簽核表不能另行改寫。
- 文件與報告設定繼續使用既有欄位 ID。增加第 4 台設備的儲存格選項，共有 132 個階段對應項目，上限仍為 224 組對應。
- 第 3 區準備填寫保存後，已對應的答案可出現在唯讀委託單；尚未簽署時，簽名、姓名及簽名日期保持空白。
- 第 4 區使用「執行者試驗前確認」下的檢核、簽名圖檔與日期欄位。另保留「執行者完成」的簽名，供完成試驗的獨立欄位使用。
- 一階尚未簽名時，範本預覽可顯示目前有效排程的參數，保持簽名空白。簽名後改由已凍結的階段紀錄產生。
- 原稿、範本綁定、儲存格設定與已送簽的文件內容不會被這次更新重寫。

## 版本與完整性

Migration 047 記錄工作區切換時間。已在切換前完成一階簽核的文件維持原來的排程順序；尚未接收的案件改用試驗前準備及無異常簽名。已接收的歷史案件保留原來的簽核意義。

一階簽名會重新核對委託版本、樣品編號版本、排程版本、試驗規範、設備及人員狀態與占用。任何版本失效都須重新確認，不會自動重排或替換簽名。二階核准時若開始日期已過，須退回重排。直接呼叫舊核准／接收 RPC 也不能略過新流程的必要條件。操作回應不明時查詢原操作，不會自動重送簽名或保留資源。

新增四張私有表只供受控 RPC 使用，啟用 RLS 並撤除瀏覽器角色的直接存取。原有資料列、公用 schema 與不相關函式使用雜湊比對確認保留。

## 驗證與發佈

前次驗證與 Preview 紀錄見 `verification.json`；048 修正的驗證見 `verification-048.json`，最新 Preview 以 PR49 連結為準。所有資料庫流程測試都在無網路的本機合成資料庫中執行並回滾；沒有用真實委託驗證簽核或啟動。雲端 migration 先作完整回滾探測，再以單次收據安裝，回應不明只讀回查詢。

交付維持 PR49 及受保護的 Preview，不合併主線，不部署 Production 前端，不更動持久環境變數、SSO 或 Render 服務設定。Migration 安裝於共用後端，因此後端的新流程規則會影響切換後尚未一階簽核的案件；使用本次 Preview 操作這些案件。

## 排程、編號與試驗前流程修正（048）

排程草稿先以空白樣品編號確認。編號儲存須提供目前排程草稿版本，伺服器重新核對後將編號附入同一份排程並遞增版本；修改排程後必須重新確認編號才能簽署。

執行者以單一綠色勾勾開啟準備表，檢核合格後接續確認無異常與實際簽名。虛擬案件同樣必須完成這兩步才能進入加速器，準備表本身不要求先加速。紅色 X 僅送出取消申請；等待一階主管於排程編輯器核准或駁回，不會由執行者直接取消或釋放資源。
