# Authoritative schedule completion dates and E2

Shared schedule dates are calculated by the backend planner. A dedicated authenticated `POST /api/business/planning/preview` accepts `{command}` and returns an unreserved plan without creating an operation receipt, saving a draft, reserving equipment or invoking a model. The command uses the existing signed request, planner-entered U, resource revisions, executor, start date and buffers. The preview ignores the supplied placeholder finish date and calculates it using the same planner used by save/booking.

Migration025 extracts that calculation into a private helper, leaves the existing strict `schedule_draft_plan` entry point in place, adds the authenticated preview RPC, and makes formal booking persist its whole-day reservation boundaries. Permissions, tenant isolation, signed request/document revisions, equipment/executor revisions, capacity, weekday/continuous calendars, daily equipment hours and reservation conflicts remain enforced. The private helper cannot be invoked by browser roles. Saves and booking still reject a finish date that differs from the calculated date.

The existing form shows a read-only calculated finish date for shared database schedules. The user subsequently required whole-day batching and occupancy; see day-based-scheduling.md. It refreshes after relevant inputs change and blocks save/booking until the current preview succeeds. Late or aborted responses cannot replace a newer result. The save command contains exactly the confirmed finish date. Demo/manual forms retain their existing editable finish field. The local serial calendar helper also respects each equipment item's daily hours.

E2 candidate search now computes one finish date per candidate using the same helper; its search interval bounds candidate start dates, so a long trial may finish after that interval. Candidate commands are deduplicated, and selected candidates are revalidated before filling the form and again before saving/booking. E2 ranks supplied, validated candidates; it never invents equipment, executors, dates or allocation rules. The original candidate panel now shows model, token usage and estimated cost from the verified response.
