# 共用規格參數

在「系統管理 → 試驗與設備參數 → 共用試驗項目與方法」按 **新增規格參數**，可建立種類名稱及可用單位，例如「流量」搭配 `L/min、m³/h`。同一視窗可編輯、刪除既有種類；名稱修改保留原識別碼，試驗條件及設備技術規格同步顯示新名稱。每個工作區最多64種，每種1～12個不重複單位。

試驗的「數值／正負差」與設備的「規格上下限」維持原有行為。自訂種類同樣參與設備篩選：兩端必須使用相同種類及可比較單位，設備規格必須涵蓋完整試驗容許範圍。新增單位不會自動建立單位換算；自訂單位以相同單位比較，既有已支援換算維持原行為。

清單顯示試驗、設備及已保存計畫的使用數量。被使用的種類無法刪除，被使用的單位無法移除；仍可修改名稱或增加單位。歷史計畫也保留參照保護，避免清除現有來源後破壞已保存計畫。刪除未使用的預設種類後不會在重開時自動還原。已停用種類不能由舊編輯視窗重新儲存。

管理功能沿用 `catalog.manage`；一般工作區成員只取得選單所需的基本種類資料，不能讀取管理使用數或異動。原生儲存以工作區及登入會員核對，使用版本檢查、準備／提交及操作結果查詢。回應中斷時先查結果，不自動重送。Demo模式使用本機清單，不寫入原生資料庫。

Migration `061_shared_specification_parameters.sql` 新增受保護的種類與操作紀錄表，讓試驗及設備共用同一套驗證。預設8種採讀取時解析，不回填既有案件或設備。部署前核對001～060的完整清單及既有函式，回滾演練確認既有資料、權限及public schema保留；001～060不重跑。

驗證使用合成資料與傳輸替身：完整Node1067項、新增規格參數PostgreSQL29項、既有試驗編輯器16項、設備規格22項與資源管理46項均通過。桌面／手機10項驗證涵蓋新增、修改、刪除、兩處選單同步、參照保護、儲存回應中斷查詢與權限；固定視窗標題後另重跑相關6項。建置與lint完成，lint仍有非阻擋警告。未呼叫模型、寄信或推進真實案件。

## 網站入口修正

「規格參數管理」出現 `ROUTE_NOT_FOUND`，是因為外層API入口未將規格參數路徑加入允許清單；讀取被拒絕後，新增表單維持停用。補上context、prepare、execute及result四個明確路徑，繼續保留登入、來源、工作區及管理權限檢查，不開放任意子路徑。

新增HTTP整合驗證會穿過實際固定入口與Vercel rewrite，再到認證handler及規格參數API。瀏覽器規格參數測試也改為走同一入口，只有資料庫傳輸使用合成替身，避免僅測試內部處理器而漏掉入口設定。驗證新增、修改、刪除、讀回、結果查詢、權限拒絕及不明路徑。此次修正不需要資料庫migration。
