## 展示操作

所有帳號密碼均為 `demo1234`（僅虛構 Demo）。使用同一瀏覽器、同一網站。

1. 首頁依序查看電子委託、LMS、實驗室及驗證計畫入口，確認可返回首頁。驗證計畫不登入。
2. 電子委託以 `requester@example.com` 的「委託者登入」建立草稿、修改產品代碼、刪除草稿。
3. 重新新增一筆，使用 Demo 填入後確認資料，送出主管簽核。
4. 以 `supervisor@example.com` 的「主管登入」查看案件。退回需原因，核准需簽名。可先演示退回，再由委託者在清單「編輯並重新送出」。
5. LMS 先以 `level1@example.com` 核准第一階，再以 `level2@example.com` 核准第二階；不得跳階或自行簽核。手寫／上傳／預設圖片均為 Demo 簽名。
6. 排程管理查看新案件，填樣品編號、設備、工程師、未來日期。可先展示容量超限、設備類型不適用及溫濕度超規格被拒絕。
7. AI 自動化排程是規則搜尋，三秒後帶入候選，須人工確認並儲存。
8. 實驗室以 `chen@example.com` 登入，在開始日期前確認接收。確認後顯示已排程；重新整理應保留。
9. 系統日期到達後才進入試驗中；不要為現場展示修改電腦時間。實際時間完成流程與報告處理使用獨立的預置 Demo 案例說明。
10. LMS 可用 `huangxm@example.com` 管理員演示設備、物料、報表及 AI 問答。AI 回覆逐字出現，並未呼叫模型 API。

首次登入可能自動建立一筆明確標示的完整流程範例；這不是現場逐步操作的證據。E2E 使用空白工作清單並停用這筆一次性範例，從真實表單建立新案。

## 重現驗證

```sh
npm ci
npm run lint
npm test
npm run build
npx playwright install --with-deps chromium
npm run test:e2e
```

雲端環境已有系統 Chromium 時可用：

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/lib/chromium/chromium npm run test:e2e
```

E2E 每個案例使用獨立瀏覽器 context，只寫入虛構測試資料；測試開啟本機 4173 port，不連正式網站。失敗時保存 trace。
Node 測試須確認輸出是逐項測試名稱及斷言結果。若沙箱僅回報檔案名稱，需要在允許子程序的環境重跑，不能把檔案層級結果當成完整測試。
