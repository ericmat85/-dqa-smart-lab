## 統計及語意規則

- 時區：Asia/Taipei。即將到期為今天起至未來第 3 天（含）；需求逾期為需求日期早於今天。
- 缺少／無效需求日期不納入日期提醒，顯示「未提供」。終止／取消／結案不納入。
- 「本月核准」按 `approvalDate` 所在台灣日曆月，不按案件最後更新時間，也不固定展示數字。
- 優先順序：逾期 → 急件／專案關鍵 → 需求日期早 → 最後更新／建立較早；沒有日期排最後。等待天數用最後更新／建立時間計算，缺少時間為未提供，不推算簽核送達時間。
- 草稿沒有真正簽署時間，不以建立日期冒充簽名日期；表單顯示「尚未送出」，實際送簽仍由原流程記錄時間。
- 主管的全部委託單維持將待查閱分流到查閱清單；委託者可在自己的清單唯讀追蹤待查閱，確認查閱仍限指定主管。
- 狀態為「已完成」的既有資料代表試驗完成；報告待審核、待查閱、結案仍由原報告流程維護。沒有批次更名或改寫狀態。
- 儲存退件補件中的內容時保留原案件狀態，重新送簽才使用原服務切換為待主管簽核；完整簽核歷程保留。

## 資料相容性與失敗處理

- 繼續讀取原 `dqa-request-demo-v2` 與既有欄位，沒有資料遷移、清空或更換 key。
- 新增可選 `draftSignature` 保存尚未送簽的簽名草稿；不寫入正式簽核歷程或簽署時間，重新開啟僅作為可修改的圖片，送簽仍由本人按鈕確認並通過原驗證。舊資料沒有此欄位仍可讀取。
- 不再於每次登入自動建立案件或彈出 Demo；仍可在新增表單按 Demo 填入。
- 編輯保持既有快照比對，防止舊編輯器覆蓋新版。表單寫入確認成功後才離開／顯示成功；配額／儲存權限失敗保留內容。
- 報告 IndexedDB 讀取／中繼資料同步失敗會保留已提交資料與快取、顯示可重試訊息，不把錯誤當成空清單。
- 不再用背景自動寫回整批電子委託快照，避免讀取失敗時以空陣列覆寫資料。破損本機資料顯示錯誤並保留原文，提供重試。
- 本地 Demo 並非多使用者後端交易；正式並行編輯仍需伺服器版本控制。沒有對此宣稱正式安全隔離能力。
- 簽名仍是 Demo 圖片，不具正式電子簽章效力；PDF 仍僅在委託者主管確認查閱後封存。
