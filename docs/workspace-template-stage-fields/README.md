# 委託單收件確認、排程確認及階段簽名

依使用者確認的原稿分工，26–35列對應 LMS 一階審查，36列對應 LMS 二階簽核；24列既有委託者及直屬主管簽名保留。37–42列的檢核及接收簽名出現在實驗室「確認接收」視窗；執行過程異常也可在完成試驗時確認。

| 階段 | 本次新增填寫 |
| --- | --- |
| 一階審查 | 新產品／設計變更／其他許可類別及說明、需求許可、規範及判定基準、委外與預計完成日、設備工具夾具與預計完成日、測試件編號、三組耐久設備及預估使用起訖、測試人員、計畫開始日、報告產出日 |
| 二階審查 | 沿用實際簽核視窗的簽名；新增可指定姓名、簽名圖檔與日期的映射 |
| 執行者接收 | 樣品正確性、數量、收樣日、治工夾具及改善日期、熟悉操作及改善日期、委外預約及完成日期、目前異常及說明、實際簽名 |
| 執行者完成 | 執行異常與說明、實際完成簽名；完成結果取代紙面異常欄位，原始接收答案仍留存 |

「系統管理 → 文件與報告設定 → 委託資訊自動代入 → 工作區預設委託單 → 編輯儲存格對應」按階段分組列出欄位。每個是／否選項可分別對應勾選格；簽名圖檔、姓名與簽名日期分開指定。所有日期另外提供年／月／日三個欄位，適用原稿中用斜線分隔的日期位置。合併格仍指定左上角，簽名按圖片比例縮小至該格／合併區內。最多224個對應，涵蓋123個新增階段映射及既有委託資訊；不推測或自動覆蓋使用者座標。

階段欄位只提供給委託單，試驗報告範本仍使用既有獨立映射與報告簽核頁。對應只影響之後送簽並固定版本的委託；既有文件與映射不回填。僅實際被該版範本對應的輸入族群必填，條件日期依是／否答案檢查，其他與異常選取後必填說明。無對應時可選填，舊流程可繼續。接收時異常可選「尚未執行」，完成時已對應的異常欄位須回答是或否。

預覽從實際簽核紀錄取得階段姓名、時間與簽名，不接受表單提交者指定簽核人或簽名來源。原始送簽 payload、原稿與雜湊不改寫，階段新增資料另外綁定不可變的簽核事件及排程。委託單仍唯讀，提供執行者編輯／下載的是試驗報告。重新排程後，只顯示目前有效排程的接收／完成紀錄，不沿用舊排程簽名；完整簽核歷程保留。

映射編輯器的「模擬委託資料（不儲存）」新增各階段填選與合成簽名開關，可在縮放的 Excel 預覽確認位置。不產生真實簽核，不更新任何案件；模擬簽名明確使用 SIMULATION 圖片。

資料庫046新增兩個私有資料表、受權限保護的階段操作包裝及簽核事件觸發器。填選值與原有簽名、角色、文件版本、排程修訂、接收時窗在同一交易確認；直接呼叫既有 RPC 也不能略過已對應的必填檢核。同一操作不可換資料重送；失去回應時沿用原操作查詢，不自動重送。原本的退回、本人簽名、不同階主管與執行者權限檢查保留。

驗證使用合成 API fixture 與隔離、無網路的 PostgreSQL；所有 SQL 測試交易回滾。未修改使用者上傳原檔、範本綁定、現有映射或案件，也未執行實際清理或初始化。

本機完整956項程式／API測試與最後147項相關檢查通過；28項新增階段、40項委託簽核、38項人工作業及40項映射SQL測試均通過並回滾。新增階段桌面／手機8項案例通過；其他回歸與最終Preview見PR49。建置、Lint（既有專案警告）及diff檢查通過。046先完成雲端回滾探測，再單次安裝與讀回，所有既有資料、設定、綁定及原稿保留。
