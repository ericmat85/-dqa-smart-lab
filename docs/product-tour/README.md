# 機器人九階互動導覽（電腦版）

首頁或既有 AI 助理中的「機器人九階導覽」開啟 `/tour`。

這一版直接顯示原有 RequestApp、LmsApp、LabApp 及其表單，不再使用獨立仿製案件卡片，也不由下一步代做業務動作。機器人在目前操作位置旁提供浮動解說，並在原畫面為下一個操作加藍色外框。

## 遊客操作

1. 待簽核：開啟委託、DEMO 填寫、主管核准。
2. 待審查：分別切換模擬一階及二階主管，使用原簽名與核准按鈕。
3. 待排程：開啟編輯排程、填樣品使用空間、操作 AI 排程、儲存。
4. 待確認：確認接收，關閉範本下載視窗，按既有 Demo 加速器開始試驗。
5. 試驗中：先按操作欄的「設備狀態」查看本案設備並關閉視窗，再按加速器完成此筆模擬試驗。
6. 已完成：提交報告、DEMO 填入、等待檢查、實際送出。
7. 待審核：二階及三階主管分別開啟 Excel 報告、簽名並核准。
8. 待查閱：指定主管檢視報告，可先預覽版面，再確認查閱與封存。
9. 已結案：到原資料庫查看或下載結案 PDF。

共有 11 個操作檢查點，涵蓋九階，因需求審查與報告審核各有兩個角色。只有偵測到真實資料狀態已完成目前操作，才開放前往下一環節；最後還需要實際開啟 PDF 或下載，才可完成導覽。下一步僅導覽換頁與切換隔離帳號，沒有直接呼叫核准、排程或報告提交捷徑。

## 資料隔離與規則

- `createTourSeed` 僅建立一筆待簽核假委託，沒有自動推進流程的方法。
- 在同來源隔離工作區載入原有 App；啟動前將該視窗的 localStorage／sessionStorage 換成獨立記憶體儲存。
- 報告使用獨立 `dqa-tour-reports-<唯一識別碼>` IndexedDB，沿用相同報告元件與儲存介面；正常工作區仍使用原 DB 名稱。離開／重新開始時只刪除此導覽 DB。
- 重新載入內部操作視窗可從外層記憶體快照恢復；完整重新整理導覽頁則重新開始。內部換頁或重載都先重新安裝隔離，再載入 App。
- 沿用原權限、主管角色模式、簽名、退回、取消與中斷檢查。不擴大實際使用者權限，不改現有案件、帳號或登入身分。
- 外層僅接受來源視窗、同來源 origin 及 token 都符合的進度訊息；一般主視窗送來的假進度無效。
- 所有帳號、案件、圖片簽名、Excel 與 PDF 為 Demo。試驗時間只用既有加速器模擬；沒有後端或 AI API。

- Lint、diff check、Production Build 通過；既有大型 JS bundle 警告保留。
- 最終全套單元測試 49 個檔案通過，0 失敗。
- 正式建置的九階實際操作（深／淺色）、重載與資料隔離、一般啟動共 4 項 E2E 通過。
- 一般登入、跨系統入口、雙階需求審查、報告退回重送簽核結案及原加速器共 5 項相關回歸通過。
- 額外 5 項正式建置測試通過：外部字型完全阻擋時仍能啟動，以及 1366／1920 深淺色登入畫面。
- 新增私有 Storage、導覽 DB 名稱驗證、操作完成門檻及單筆待簽核種子測試。
- 本次僅驗證電腦版 Chromium；不新增手機功能，未重跑完整全部 E2E。線上結果以 PR CI 為準。

## 加速器與提交後進度修正

加速器不再自動建立新案件；僅加速已排程、已接收且等待開始的現有案件，或完成同一筆已標記的加速試驗。導覽額外指定案件編號，接收前、未查看設備及本環節完成後的誤按只顯示操作指引，不推進業務動作或建立其他案件。

導覽進度接受已完成的後續狀態，避免快速重複操作或報告狀態已更新後，因只比對單一舊狀態而卡住；報告讀取使用本案已同步的版本資訊，不會改追蹤其他 Demo 案件。現有簽核、退回與權限條件維持。

## 桌面大畫面與入口改善

- 工具列縮小、操作區增高；預設為全寬操作畫面，解說可隱藏，操作列仍保留下一步與解說入口。「全螢幕」使用瀏覽器全螢幕 API，Esc 可退出；不支援時仍放大操作區。
- 首頁導覽入口與下一步有輕微邊框光暈，工作區標示不移動按鈕；尊重減少動態效果偏好。
- AI 助理入口縮成內容寬度，使用既有 SPA 導覽事件；Vercel 加入 /tour rewrite，支援直接開啟與重新整理。
- 單台設備直接開啟原有設備資訊，不再先顯示選擇框；多台設備仍可選擇。
- 導覽結案預覽改用 public/images/tour-demo-report.svg 的 Demo 報告示意圖，避開 iframe PDF 檢視器被瀏覽器封鎖。圖中資料明確標示虛構，非實際試驗結果或正式 PDF 內容。一般資料庫 PDF 預覽與下載機制維持。

## 跟隨位置的浮動解說與多機台操作

- 導覽預設保留全寬實際系統畫面，解說浮在目前操作目標旁，不另佔右側欄。下一個目標改變時自動更新解說；捲動或視窗大小改變時重新定位，避免遮住該目標。
- 可暫時隱藏當前提示，下一個操作位置會再次提示；完整步驟放在可展開內容中。無自動點擊、無搶焦點，所有動作仍由遊客操作。
- 排程視窗在桌面放大至接近視窗大小，表單可捲動，儲存與其他操作固定在底部。
- 多機台改為勾選式附加設備，顯示已選／所需台數，不再使用被單行樣式壓縮的原生複選 select。設備類型、狀態、容量、時段、資源衝突與儲存驗證仍沿用原邏輯。

## 舊版 LMS 多機台加速相容

原有 LMS 委託以獨立審查清單保存，不一定有電子委託資料。加速器現在也接受既有 LMS 清單中雙階審查通過的案件，並保持接收與排程版本、等待開始、待核准操作、取消及設備衝突檢查；不會為此建立電子委託副本。兩台設備一起進入使用中並在完成後依原有清理保留規則釋放。
