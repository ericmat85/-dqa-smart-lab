# 列表勾選批次自動化排程

在「試驗排程管理」勾選可安排的案件，按「自動化排程」設定最早及最晚開始日期、樣品空間 U 與設備台數。可跨頁保留選取，每批最多 20 筆；全選僅針對目前頁面可安排的案件，超量會提示，不會截斷選取。

「產生批次安排」依急件、專案、一般、委外及需求日期排序。使用資料庫中的試驗、適用設備、技術規格、空間、執行人與日曆規則驗證；整日安排沿用 24 小時進位，例如 250 小時占 11 天。複合試驗依已簽核的階段來源分別選設備。新流程的樣品編號仍須另行手動填寫及儲存，批次安排不產生編號。

逐筆結果顯示可安排的日期、設備與執行人，或資料不足／無可用時段的原因。確認後可一次儲存所有可安排的草稿；待處理案件保留既有資料。保留原有草稿備註及準備／清場時間。草稿不保留正式資源，也不更動簽核階段；原簽核及正式預約規則持續適用。原單筆 AI 排程保持可用。

## 交易與範圍

- 原生權限及工作區範圍控制，僅可安排有權限且尚未正式排程的案件。
- 預覽核對同批案件間及未替換草稿的設備／人員衝突。搜尋最多 32 個開始日期、每案 160 次驗證、整批約 11 秒，達上限的案件明確標示待處理。
- 儲存前重新核對全部可安排案件的來源版本、設備、執行人、日曆及草稿衝突，再於單一交易執行既有排程草稿命令；任一步失敗則整批回復。
- 操作識別碼、成員綁定、10 分鐘到期及憑證查詢防止重送。回應中斷後由使用者查詢結果；不自動重送，也不因重新整理重複儲存。
- 新增 `/schedule-batches/prepare`、`/execute`、`/result/:id`，透過既有固定 BFF 與 Vercel rewrite，嚴格限制欄位、查詢及登入。
- 新增 063 遷移：一個私有 RLS 操作表、索引與七個函式；不修改既有函式，不回填或改寫既有業務資料。001–062 不重播。
- 本批次功能使用原生規則安排，不呼叫模型供應商、不發信、不自動簽核案件。

## 驗證

Node 包含列表選取、嚴格命令、實際 HTTP 路由、失聯回應與憑證。PostgreSQL 回復交易測試涵蓋優先度、同批衝突、既有草稿、日期進位、部分待處理、虛擬／委外、版本變動、原子回復與複合階段。瀏覽器測試涵蓋桌面／手機勾選、跨頁上限、批次預覽與儲存、重載查詢、權限及原單筆排程回歸。
