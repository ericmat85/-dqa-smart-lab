本次保留既有介面、簽核階段、排程日制、報告限制、模型選擇與預算設定。未變更資料庫結構、正式資料、寄信設定或正式站部署。

## 確認原因與修正

| 類別 | 原因 | 處理 |
| --- | --- | --- |
| CI 模式 | 共用啟動模式沒有涵蓋 Demo、私人 Preview、資料庫及資料庫 AI 的不同前端設定 | 每個測試檔只歸屬一種模式，伺服器明確覆寫模式環境變數；使用合成 API 回應。常見問題使用程式答覆；舊 Demo 的 E2 仍需 API transport，因此提供本機合成閘道，執行真正的確定性排程規則，模型選擇使用合成回應，避免誤呼叫不存在的端點或付費模型 |
| 額外瀏覽器 | 部分簽核測試的第二個瀏覽器固定連向舊連接埠 5198 | 改用該測試專案的實際網址，加入防止固定網址回歸的檢查；本機設備閘道 fixture 的 CORS 也只允許該專案的實際來源，正式閘道規則維持不變 |
| 工作逾時 | 大型版面檢查與桌面／手機流程集中在少數工作 | 改為 12 組：Demo 6、Preview 2、資料庫 3、資料庫 AI 1；每組仍限 20 分鐘、兩個工作程序、不自動重試 |
| 附件額度 | GitHub 帳號畫面顯示 0.5GB／0.5GB；可列出的四個倉庫沒有可刪除附件 | 減少 CI 成功截圖，保留失敗截圖與 Trace；附件上傳失敗時仍寫工作摘要，測試失敗照常失敗 |
| 連線等待 | 共用資料請求及部分檔案讀取缺少完整等待上限，收到回應標頭後仍可能卡在讀取內容 | 對完整請求與內容讀取設定上限，逾時結束相應讀取狀態 |
| 背景同步 | 每 15 秒的同步也占用前景讀取指示；離開共用設定未取消讀取 | 背景同步不占用前景指示；離開設定即取消該頁未完成的讀取 |
| 上傳測試 | 超過 10MB 的照片報告，單次合成儲存 PUT 實測 8.878 秒；加上後續提交超過舊 10 秒斷言 | 該大型檔案測試使用 30 秒提交斷言及 90 秒整體預算；保留所有檔案與資料庫結果檢查 |
| 舊斷言 | 部分測試仍尋找已集中至維護區的刪除按鈕、L 單位、AI 常見問題回覆及舊範本列表 | 更新已能從目前程式確認的舊選取方式；其餘版面落差保留失敗證據，未更改畫面來配合測試 |

等待上限：資料讀取 60 秒、儲存 90 秒、AI 請求 120 秒、報告上傳 120 秒、字型／範本／示意圖每項 60 秒。這些是連線界限，不代表操作必須等待到上限。

已送出的儲存或模型請求若逾時，保留「結果待確認」與原操作識別，不自動重送。另一個讀取者取消，不會取消共用的登入更新。過期請求收到較晚的 401 時，也不會重新登入後重播異動。

## 實際阻斷錯誤

「依設備排程」有資料時，`EquipmentScheduleBoard` 讀取未傳入的 `canEdit`，造成 `ReferenceError`。已將父層既有權限值一路傳入，保留原畫面與編輯規則。三個設備分組案例及兩個桌面／手機唯讀案例重測通過；唯讀角色的編輯按鈕仍停用。另啟用前端未宣告變數的 lint 檢查，避免同類錯誤漏過 CI。

## 驗證範圍

瀏覽器驗證使用本機 Chromium、合成帳號、合成資料及攔截的 API；沒有操作正式案件、寄送郵件或呼叫付費模型。GitHub Actions 未在雲端重跑。本機分組耗時不包含 GitHub 安裝時間，不能當作雲端全數通過的證明。

12 組蒐集共 764 個桌面／手機案例，確認沒有重複分配。只有已完成並有結果的案例可計為通過；跳過、未執行與失敗分開列示。部分舊版面測試仍需對照既有設計，完整瀏覽器套件目前不能宣稱全綠。

完整模式與診斷設定見 [ci-browser-validation.md](ci-browser-validation.md)。實際本機結果與截圖會隨本次交付列出。
