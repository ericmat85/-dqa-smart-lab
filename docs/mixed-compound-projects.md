# 同專案混合一般試驗與複合連續試驗

在電子委託單選擇「專案」，於「試驗項目」保留「獨立分項（可加入複合組）」：

1. 「新增專案試驗項目」加入一般試驗。
2. 「＋新增複合連續試驗」建立一組，填寫名稱及共用樣品數量。
3. 在該組內加入 2～20 個子試驗，依序設定工時、運轉方式、試驗手法及判定基準；可調整順序、複製或移除。
4. 可再新增其他複合組，與一般試驗一起儲存草稿或送簽。每個一般項目、每個複合組各建立一張關聯委託單，屬於同一專案。
5. 儲存後從清單重新編輯各組的草稿；審查及排程沿用既有流程。清單與試驗摘要會顯示複合組名稱。

每組共用同一批、相同數量樣品，子試驗依序連續銜接。不同組可有不同樣品數量及試驗流程，不會互相覆蓋；組與組之間不會自動建立先後依賴。

每個專案最多 100 個分項，一個複合組計一項；每組最多 20 個子試驗，共用樣品數量 1～1000。複合組不能再嵌套複合組。原有整份專案作為單一「環境複合連續試驗」的方式仍可使用。

各組的條件來源、設備規格篩選、假日規則及資源衝突檢查沿用原生複合排程。可在排程列表選取多筆同專案項目，一起預覽及儲存排程草稿。完成正式核准前仍須完成樣品編號、審查與簽名；未核准的排程草稿不會占用正式資源。

## 驗證與資料層

- 既有專案 BFF prepare／execute／result 路由加入嚴格的分項 compound 欄位檢核，拒絕額外 scope 或階段欄位。
- 064 migration 僅擴充三個既有私有驗證／資料組裝函式；保留原生專案原子交易與重試結果查詢，不回填舊案件。
- 每組獨立保存 `compoundLabel`、`compoundStages`、`compoundVersion`；一般項目不附帶複合流程。子試驗引用當前工作區的試驗 ID 及 revision，原生資料庫再次核對。
- 驗證涵蓋混合專案建立、草稿重開、不同組隔離、文件凍結、重試不重複、目錄過期／跨工作區引用、交易失敗回滾、逐階段排程與選取混合項目的批次排程。瀏覽器使用合成資料及實際 HTTP BFF 邊界；未建立真實驗收案件或呼叫付費模型。
