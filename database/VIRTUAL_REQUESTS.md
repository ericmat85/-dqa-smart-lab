# 虛擬委託與真實委託

新增委託時選擇「真實委託」或「虛擬委託」；Demo 填入自動選擇虛擬。種類在首次儲存時由獨立資料庫欄位固定，送簽文件與雜湊包含種類。既有案件及未傳種類的舊用戶端預設 REAL，不依品名、備註或舊 Demo 使用紀錄重新分類，也不改寫已簽署文件。

兩種案件沿用同一套委託者、直屬主管、一階／二階審查、排程與執行人接收流程。虛擬案件的 BOOK 建立原生排程，但不建立實體設備占用，亦不保留執行人時段；規格、容量、版本及授權仍驗證。真實排程不受虛擬排程占用影響。

已接收虛擬案件可向 AI 助理輸入 `/accelerate`；這個命令只開啟介面，不呼叫付費模型。管理者或被指派且有權限的執行人逐次確認 50%、100%。後端以原排程時窗計算虛擬時鐘，直接推進同一個 requests／schedules 的 RUNNING、COMPLETED 狀態。原工時與起訖日期保留，實際開始／完成時間另外保存，並記錄操作者、操作識別與追加稽核事件。工作區時鐘只自動開始 REAL 案件。

100% 後可提交報告、二／三階主管審核與指定主管查閱封存；加速器不生成簽名或代替主管核准。上傳的 Excel 必須保留綁定本案的虛擬標示工作表及各表列印標頭；產生的 PDF 每頁標示測試用途，後端也驗證。虛擬報告不能上傳為真實案件報告。通知信標示虛擬測試用途。

舊的 027 副本紀錄保留供查閱；不能再建立副本或把真實案件透過該端點加速。新操作沿用受保護的 `/flow-tests` API 路由，但用途是原生 VIRTUAL 流程；不能傳入任意百分比或虛擬時間。操作 UUID、雜湊及版本用於防重送；不確定結果只查回原操作。

套用 028 必須以 027 為基準，在一個交易中執行。函式修改會比對原函式定義，基準不符就中止；不修改 001–027。測試使用無網路的本機 PostgreSQL、合成案件與受控瀏覽器 API，沒有對雲端既有資料分類、加速、寄信或呼叫模型。
